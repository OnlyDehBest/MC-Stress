Built to stress the server, not your machine

No headless game clients, no Node runtime — every bot is a few kilobytes of async Rust speaking the Minecraft protocol directly.

Raw protocol clients

Handshake, login, configuration and play states implemented by hand on tokio. Compression, keep-alives and teleport confirms handled per bot.

Live dashboard

An axum web console streams bots online, movement, server latency and errors over WebSocket every second, with a load-over-time chart.

Breaking-point detection

Bots join in configurable batches and intervals; MC-Stress pings the server continuously and flags the load where latency and kicks spike.

Multi-protocol

Auto-detects the server version via Server List Ping, or pin one manually. Packet IDs are mapped per version from 1.20.2 up to 26.3.

Realistic players

Per-bot view distance, spawn dispersion, walking and sprinting at vanilla speeds — so each bot costs the server about what a real player does.

Player activity

Optional chat messages, commands and arm swings on a timer, to exercise chat plugins, command handlers and packet listeners.

Seven bot models, light to heavy

Pick how much each bot costs the server — from a parked connection to a sprinting explorer streaming fresh chunks.

Quick start

Requires a Rust toolchain. The dashboard is bundled into the binary.

1

Build and run

$ git clone https://github.com/OnlyDehBest/MC-Stress
$ cd MC-Stress
$ cargo run --release
2

Open the console

Go to http://localhost:3000. Set PORT to change it:

$ PORT=8080 cargo run --release
3

Configure and press Start

Host, port, bot count, batch size, interval, view distance, dispersion and bot model. Run /spark tps alongside for true TPS.

The target server must run with online-mode=false, and movement anti-cheat should be disabled during the test (bots move on a constant y). Only stress-test servers you own or are authorised to test.
